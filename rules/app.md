# アプリ開発（Tauri / Web / CLI）共通ルール

このファイルは `~/.claude/rules/app.md`。SessionStart hook により、`package.json` か
`src-tauri/` を持つプロジェクトでのみ context に自動注入される。
グローバル CLAUDE.md の原則に加えて、以下を守ること。Unity プロジェクトは `rules/unity.md` を見る。

## このファイルのルールの扱い

- ここに書いてあるのは**既定**であって絶対ではない。合わないと判断したら破ってよい。
  ただし**破ったことと理由を報告に 1 行書く**（黙って破らない）。
- 例外を持つルールには、そのルール自身に例外条件を書いてある。書いていないものは既定どおり従う。

## 技術スタックの既定

指定が無ければこれを選ぶ。理由なく別のものを持ち込まない。
ただし **GUI が要らないなら Tauri にしない**。CLI やスクリプトで済むものを 1 アプリに仕立てない。

| 種別 | 既定 |
|---|---|
| デスクトップアプリ | Tauri 2（Rust + React + TypeScript + Vite） |
| Web サービス | Cloudflare Workers（Hono + D1 + Drizzle）+ React SPA |
| Python | uv（`uv run ...`） |
| アイコン | **lucide-react**（React 系は既定で導入する） |

## プロジェクト固有 CLAUDE.md の構成

新規に書くときも既存を直すときも、この 4 節に揃える（既存プロジェクトが全てこの形）。

1. **1 行の説明 + スタック** — 詳細な設計背景は `README.md` へ逃がす
2. **検証コマンド** — コピペで動く形で列挙する
3. **アーキテクチャ要約** — ディレクトリ責務の表 + **依存方向**（例:『依存は `ipc → core → {io, record}`。逆流させない』）
4. **触る前に必ず確認すること** — 罠を「症状 → 原因 → 対策」で書く。回帰テストがあるならテスト名を添える。
   **直った罠は消すか README へ移す**。溜め続けると読まれないサイズになり、書いた意味が無くなる

## 検証

- **複数ファイルを直してから最後に 1 回**まとめて検証する。編集ごとに回さない。
- 既定の検証セット。プロジェクト CLAUDE.md に書いてあればそちらを優先し、
  **`package.json` / `Cargo.toml` に実在するものだけ**流す（無いスクリプトを叩いて失敗させない）。

```bash
npm run typecheck                                          # TypeScript
npm run build                                              # 型検査 + バンドル
npm test                                                   # フロントの単体テスト（vitest）
cargo check --manifest-path src-tauri/Cargo.toml --all-targets
cargo test  --manifest-path src-tauri/Cargo.toml --lib
```

- GUI を持つものは**起動してキャプチャで確認**するまでが修正（win-gui / playwright）。
  コードを読んで「直ったはず」で報告しない。

## Tauri 固有

- **Tauri コマンドは 1 箇所へ集約**する。規模で置き場所を変える。
  小さいうちは `src-tauri/src/commands.rs`、増えたら `commands/` へ分割（`ipc/` でも可。
  実測: `commands.rs` 4 / `commands/` 2 / `ipc/` 2）。依存方向は `コマンド層 → 各モジュール`。逆流させない。
- **ブロッキング I/O は `spawn_blocking` 越しに呼ぶ**。`#[tauri::command] async fn` の中で直接叩くと
  非同期ランタイムのワーカーを占有し、取り消しコマンドが返らなくなる。
- **高頻度のイベントを UI へ生で流さない**。受信スレッドと配信スレッドを分け、
  溜まった分をまとめて 1 回で渡す（毎フレーム流すと描画が引きずられる）。
  **配信レートは用途ごとに決めて、根拠をコメントに残す**（グローバルの「当て推量の数値を書かない」に従う）。
  数値の読み取り（DMX 値・転送の進捗）は実測で 10Hz で足りた。
  波形・レベルメータ・タイムコードはそれでは足りないので、必要なレートを測ってから決める。
- **同じ identifier の Tauri アプリを 2 つ同時に起動すると、2 つ目はウィンドウが出ない**
  （WebView2 のユーザーデータフォルダを共有しているため。ログにも何も出ない）。
  `npm run tauri dev` で確認するときは、先に release 版を終了する。
  併存させたいなら dev 側の WebView2 ユーザーデータフォルダを分ける
  （`WEBVIEW2_USER_DATA_FOLDER` 環境変数、または dev 用に identifier を変える）。
- **ウィンドウの位置と大きさを覚える**。現場では置き場所が決まっている。
  最小化中（サイズ 0）の値を保存しない。モニタ構成が変わって画面外を指す場合は復元しない。
- 保存先を使い分ける。設定・プリセットは**アプリデータ**、人へ配る書き出しは **exe と同じ場所**。
- ログは画面に出した行を **`log/yymmdd-hhmmss.log`** にも残す（グローバル恒久ルール）。
  先頭行にビルドの素性（日時・コミット）を書き、どのビルドのログか分かるようにする。
  置き場所の解決を間違えないこと。
    - **`src-tauri/` 配下へ実行時生成物を書かない**。`tauri dev` がそこを監視しているため、
      ログを吐くたびにアプリが再起動し、「開いては閉じる」の無限ループになる（実際に踏んだ）。
    - dev は `current_dir` から上方向へ `package.json` を探してプロジェクトルート/`log` へ。
      配布した exe は exe の隣の `log` へ。
- **Mutex を保持したままブロッキング I/O や外部プロセス起動をしない**。
  ロックは共有データ構造の出し入れだけに限定し、`Arc` を取り出してから外で I/O する。
  保持したままだと、無関係な操作まで巻き添えで固まる（UI からは原因が見えない）。
- **受け手のいない channel を作らない**。受信側を落とすと送信は黙って捨てられ、
  「UI に何も届かない」という原因から遠い症状で出る。
- **serde の境界は Rust ハンドラより手前で落ちる**。tag 名が食い違うと
  コマンドが呼ばれる前にエラーになり、**ログに何も残らない**
  （「Tauri command が呼ばれていない」≠「JS の invoke が呼ばれていない」）。
    - `#[serde(rename_all = "snake_case")]` は頭字語・略号を含む variant で予想外の区切りになる。
      その場合は variant ごとに `#[serde(rename = "...")]` を明示する。
    - **JS が実際に送る JSON を Rust 側で `from_str` する対称テスト**を置く。
- 管理者権限を要求するアプリ（`requireAdministrator`）は、`npm run tauri dev` を
  **管理者ターミナルから**起動する。非管理者からは昇格要求で失敗する。配布 exe は UAC が出るだけ。
- `identifier` は **`jp.<組織>.<アプリ名>`**（`jp.aiacats.*` / `jp.vortex.*`）。揃えるのは**新規のみ**。
  既存の `com.*` は据え置く。identifier を変えると WebView2 のユーザーデータと設定の保存先が変わり、
  **利用者の設定とウィンドウ位置が消える**ため。
- 複数 OS へ配るものは **`build-win.bat` / `build-mac.command`** に
  「テスト → 型検査 → バンドル」をまとめる。自動更新が要るなら SignalHub の `updater.rs` が参考例。

## UI の作り

- **ブラウザで開くアプリには再読み込みボタンを必ず置く**（恒久・ユーザー指示 2026-09-05）。
  対象は exe にしない HTML ベースのもの（Shifter、SessionControl のような）。Tauri は対象外。
  ホーム画面に追加した standalone 表示にはブラウザの更新ボタンが出ないため、
  これが無いと詰まる。SSE や WebSocket が切れたまま復帰しないときの逃げ道にもなる。
    - 置き場所はヘッダー右端。`lucide-react` の `RotateCw` を 16px で、
      34×34 のアイコンボタンにする。`title` と `aria-label` は「再読み込み」。
    - 中身は `window.location.reload()` の 1 行でよい。押した感触のために `:active` で回す。
    - 検証は「押してページ遷移が起きたか」で見る。押すと実行コンテキストが壊れて
      評価結果が返らないので、戻り値では判定できない
      （SessionControl の `scripts/uiprobe.mjs --click <セレクタ>` が実装例）。
- **アイコンライブラリは最初から入れる**（React 系は `lucide-react`）。ユーザー指示（2026-09-05）。
  「1 個しか使わないから」とインライン SVG で済ませない。結局あとから増え、
  太さ・サイズ・角の丸みが揃わなくなる。1 個目の時点で入れる。
    - 導入済みプロジェクトに合わせる。実測: Shifter / RigFlow が `^1.18.0`、Sequence が `^1.38.0`、
      SessionControl が `^1.41.0`。新規は最新でよい。
    - アイコンだけのボタンには `title` と `aria-label` を必ず付ける。
- **縦に伸ばさない**。関連する値は 1 行へ集約する（min/max/lerp を 1 行、Universe/開始ch を 1 行 など）。
- **1 画面に収まらなくなったら**、グループの折りたたみ + 件数バッジ + 絞り込みをセットで入れる。
  収まっているうちは入れない（操作が増えるだけ）。
- **同じ情報を二重に出さない**（ヘッダにあるならセル側は値だけ）。
- 桁違いに数が違うものは**タブや画面を分ける**（例: 灯体 1499 と Volume 5）。
- 長くなりうる文字列は**折り返す**。見切れさせない。
- **状態は 1 箇所へ集約**する（`App.tsx` か hooks）。子コンポーネントは描画に徹する。
- フロントの構成は既存に揃える。
  `src/App.tsx`（状態）/ `api.ts`（または `lib/` `osc/`。バックエンド呼び出しの薄い層）/
  `components/` / `hooks/` または `stores/` / `types.ts`
- 相手を取り違えると一番まずい情報（接続先・書き込み先）は、設定画面を開かなくても見える位置に置く。

## 通信・プロトコル

- 両側で対になる定義（アドレス表・型・引数の個数）は、**片方だけ変えると黙って壊れる**旨を
  両方のファイルの冒頭コメントに書き、対応表を README に持つ。
- **UDP は取りこぼす前提**で作る。欠けを検知して拾い直す経路と、送信側の分割送信を用意する。
- 相手が応答を返せなくなるほどの要求を一度に投げない（窓で区切る）。
- **外部プロトコルは原典（SDK のヘッダ・公式ソース）で照合する**。旧コードのコメントを盲信しない
  （実例: `NAT_REQUEST=7` は NatNet v1.x 時代の名残で、2.x 以降は 2 が正）。
- **「排他だから無理」のような制約は実測してから設計に取り込む**。
  誤った前提のまま UI 文言まで書いてしまうと訂正が要る。
- **高頻度の受信ハンドラの中で文字列を組み立てない**。OSC のようなアドレス方式の受信は、
  ハンドラが「自分宛でないメッセージ」でも呼ばれるため、ハンドラ内の割り当ては
  **リスナー数 × 受信レート**に増幅される。比較に使うアドレスは初期化時に組み立ててキャッシュし、
  ハンドラ内では等値比較だけにする。ログ出力も、フラグで囲っても引数の文字列は先に評価される点に注意。
  （Unity / C# での実例と対処は `rules/unity.md` の「OSC 受信の作法」。
  実測で OSC 由来の GC が 47% 減った）
- **性能の当たりを付けるときは、プロファイラのサンプル名を額面どおりに読まない**。
  計測粒度によっては、呼び出し先の重さが呼び出し元のサンプルに合算される
  （実例: `uOscServer.Update()` が重く見えたが、実体は登録済みリスナー側の割り当てだった）。
