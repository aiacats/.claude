# 変異チェック

テストが「不具合を残したままでも通る」緩さでないかを、実際にコードを壊して確かめる。
壊す → 絞り込んだテストを流す → 検出されたかを記録 → 元に戻す、を一覧から回す。

## 先に読む（踏んだ罠）

- **絞り込み名が違うと 1 件も走らず、「検出されなかった」に見える**
  症状: 変異を入れてもテストが通る（ように見える）。原因: `--filter` の名前がクラス名と違い、該当 0 件で終了コード 0。
  ファイル名とクラス名は一致しないことがある（MotionForge の `FbxTests.cs` の中のクラスは `FbxRoundTripTests`）。
  → スクリプトは最初に変異なしで各テストコマンドを流し、0 件なら `BASELINE NO TESTS RAN` で止まる。変異の最中に 0 件になれば `NO TESTS RAN` と出す（`SURVIVED` とは別）。
- **変異入りのビルド成果物が bin に残る**
  症状: チェックの後に GUI を見ると、存在しない不具合が出る。原因: 最後に流した変異でビルドした exe / dll がそのまま残る（ソースは戻っている）。
  → 終わったら必ずビルドし直してから GUI・スモークテストへ進む（`dotnet build <sln>` など）。
- **CRLF のファイルに複数行の変異を当てると `NOT APPLIED (0 matches)` になっていた**（2026-10-07 BMCP）
  原因: スクリプトはファイルをバイト列のまま読み、一覧の文字列は LF。→ 今は LF で見つからず、ファイルが CRLF なら CRLF に揃えて探し直す。
- **変異がコンパイルできないと、何も確かめていない**
  症状: `BUILD ERROR`。原因: 括弧の対応を壊した・到達不能コードの警告がエラー扱い（TreatWarningsAsErrors）など。
  → 「検出された」に数えない。意味が同じでコンパイルできる形に書き直す（`for (...; false; ...)` ではなく条件を反転する、など）。
- **等価な変異は生き残って正しい**
  壊しても挙動が変わらない変異（別の条件が同じことを保証している等）は `SURVIVED` になる。
  テストを足す前に、本当に挙動が変わる変異かを読んで確かめ、等価なら報告に「等価」と書く。
- **変異を流している間は、ソースを触らない・レビューを走らせない**
  スクリプトが対象ファイルを書き換えているので、同時に編集すると戻すときに巻き戻る。読み取り専用のレビューにも、変異入りの状態が見えてしまう。
  → 裏で流している間は、ドキュメント（.md）など対象外のファイルだけを触る。
- **シェルに Python を埋め込んで一覧を作らない**（hook が止める）。一覧は Write ツールで .py として書く。

## 手順

1. **変異を選ぶ**。今回足した・直したロジックごとに「これを外したら落ちるはず」を 1 つずつ。
   境界（`<` と `<=`）、条件の片側、係数、引数の取り違え、保存し忘れ・復元し忘れ、選択中のものを使ってしまう、が効く。
2. **一覧を書く**（scratchpad に .py。書式は下）。
3. **流す**。長くなるので `run_in_background: true` で（1 変異あたりビルド + テストで 20〜40 秒が目安）。

   ```bash
   python ~/.claude/skills/mutation-check/scripts/mutrun.py <一覧.py>
   ```

4. **結果を読む**。
   | 表示 | 意味 | 次にすること |
   |---|---|---|
   | `caught by <テスト名>` | 検出された | 何もしない |
   | `SURVIVED` | 壊してもテストが通った | テストを締める（アサーションを具体的に）。等価な変異ならそう記録する |
   | `NO TESTS RAN` | 絞り込みに当たるテストが無い | 絞り込み名を直す |
   | `BUILD ERROR` | 変異がコンパイルできない | 変異を書き直す |
   | `NOT APPLIED (n matches)` | 元の文字列が 0 回か 2 回以上 | 文字列を今のソースに合わせる（直前の修正で変わっていないか） |
   | `TIMEOUT` | 時間切れ | `--timeout` を延ばすか、変異で無限ループになっていないか見る |
5. **生き残りを塞いだら、その変異だけ流し直す**（一覧を小さく作り直す）。
6. **ビルドし直す**。それから GUI 確認・スモークテスト。
7. 報告に「変異 N 件中 M 件検出。生き残り: …（等価 / 塞いだ）」と書く。

## 一覧の書式

```python
ROOT = r"D:\path\to\repo"                      # --root でも渡せる

CORE = dotnet_test("tests/My.Core.Tests", "TimecodeTests")          # --filter FullyQualifiedName~TimecodeTests
BOTH = dotnet_test("tests/My.App.Tests", "TransportTests|TimelineSessionTests")
WEB = npm_test("web", "src/foo.test.ts")       # cwd はルートからの相対。cargo_test / pytest も同じ形

MUTATIONS = [
    # (何を壊したか, ファイル, 元の文字列, 壊した文字列, テストの流し方)
    ("loop resets instead of wrapping", r"src\Core\Player.cs",
     "_position = loopStart + ((next - loopEnd) % span);", "_position = loopStart;", CORE),
    ("in point not saved", r"src\App\Store.cs",
     "            InSeconds = timeline.InSeconds,\n", "", BOTH),
]
```

- 元の文字列は、そのファイルに**ちょうど 1 回**だけ現れるように、前後を含めて長めに取る。
- 行を消す変異は、改行（`\n`）まで含めて空文字にする。
- 補助関数に無い流し方は `(cwd, ["cmd", "arg", ...])` を直接書く。
- 絞り込みは狭く（関係するテストクラスだけ）。全テストを流すと 1 件ごとに数分かかる。

## オプション

- `--no-baseline`: 最初の「変異なしで通るか」を省く（直前に同じテストを流して通っているとき）。
- `--timeout <秒>`: 1 回のテスト実行の上限（既定 280）。
- 終了コード: 全部検出 = 0 / 検出されないものがある = 1 / 変異なしで通らない = 2。
