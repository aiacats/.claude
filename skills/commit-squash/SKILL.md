# 未 push のコミットをまとめ直す

方針は `rules/taste/general.md`「push の前に、同じ作業の細かいコミットを 1〜3 個へまとめ直す（まとめる前にバックアップのタグを打つ）」。
**まとめても、コード / README / ドキュメント / claudeLog を分ける粒度は保つ**。push はまとめとは別で、頼まれたときだけ行う。

## 先に読む（踏んだ罠）

- **`git rebase -i` は使えない**（対話のエディタが開けない）。→ `scripts/squash.py` が `git commit-tree` で作り直す。
  各まとまりの「最後のコミットのツリー」をそのまま使うので、中身の作り直しが無く衝突しない。
- **並べ替えは扱わない**。元の並びで隣り合うコミットだけをまとめられる。離れたコミットを同じまとまりにしたいときは、
  間にある別作業のコミットごと 1 つにするか、まとめずに残す（無理に並べ替えると、途中のコミットが壊れた状態になりうる）。
- **子プロセスの日本語が cp932 で化ける**。squash.py は stdout / stderr を UTF-8 にしてある。自分で書き足すときも揃える（`traps/windows-shell.md`）。
- **サブモジュールは別のリポジトリとして扱う**。先にサブモジュールをまとめ・push してから、親のサブモジュール参照を進める（`traps/git.md`）。
  サブモジュールへの書き込みはユーザーの明示が要る（CLAUDE.md §3）。

## 手順

1. **一覧を出す**（親とサブモジュールそれぞれ）
   ```bash
   SQ=~/.claude/skills/commit-squash/scripts/squash.py
   python "$SQ" list --repo <リポジトリ>
   ```
   未 push のコミット・触ったファイル・種別（code / readme / docs / log）・origin より遅れている数・未コミットの変更の件数が出る。
   計画の雛形が `<repo>/.git/squash-plan.json` に書かれる（1 コミット 1 まとまり）。
   - `behind` が 0 でなければ、push の前に取り込みが要ることを報告に書く（まとめ自体はできる）。
   - マージコミットを含む範囲は扱わない（止まる）。未 push の中にマージがあるときは、`list` / `apply` に `--base <マージのハッシュ>` を付けて、その後ろだけをまとめる。
   - **サブモジュールを先にまとめ直したら、親の途中のコミットは古いサブモジュールのハッシュ（push されない）を指したまま**になる。
     親の計画に `"gitlinks": {"旧ハッシュ": "新ハッシュ"}` を入れると、作り直すときに付け替える（サブモジュールの 1 行だけが変わる。apply が元との差がサブモジュールだけかを確かめる）。

2. **まとまりを決める**。作業（ユーザーの依頼）ごとに 1 つ。種別が混ざるまとまりは作らない（apply が warning を出す）。
   まとめ方は表にしてユーザーへ見せる（どのコミットをどれにまとめるか）。依頼が「まとめて」なら確認を待たずに進めてよい。

3. **計画を書く**。scratchpad に JSON を Write で書く（シェルに埋め込まない）。
   ```json
   {"groups": [
     {"commits": ["8accaa6", "a216192"], "message": "電飾が明るすぎる問題修正"},
     {"commits": ["0ea5658", "dc0bfab"], "message_file": "C:/.../msg2.txt"}
   ]}
   ```
   - 未 push のコミットを、元の順で、ちょうど 1 回ずつ入れる。
   - メッセージは元のコミットの要点を最終形で 1 行にまとめる（途中で直したことは書かない）。
     書き方はグローバル CLAUDE.md §3「コミットメッセージはユーザーが手で書いた体裁にする」（帰属の行は付けない）。

4. **まとめる**
   ```bash
   python "$SQ" apply <plan.json> --repo <リポジトリ>
   ```
   - 先に `backup/squash-<yymmdd-HHMMSS>` のタグを元の HEAD に打つ。
   - 作り直した最後のツリーが元の HEAD と違えば、ブランチを変えずに止まる。
   - ブランチは `update-ref` で付け替えるだけ（作業ツリー・index の未コミットの変更はそのまま）。
   - 作者と日時は、各まとまりの最後のコミットのものを引き継ぐ。

5. **確かめる**
   - 出力の `tree diff vs backup: none`。
   - 各まとまりのツリーが、元の最後のコミットのツリーと同じか:
     `git rev-parse <新>^{tree}` と `git rev-parse <元の最後>^{tree}` を比べる。
   - `git status` で未コミットの変更が減っていないこと。

6. **戻すとき**: `python "$SQ" undo backup/squash-<...> --repo <リポジトリ>`（まとめた後にコミットを足していたら止まる）。
   バックアップのタグはローカルだけに置く（push しない）。push が済んで不要になったら `backup-clean` skill で消す。

7. **報告**: まとめ方の表（新しいハッシュ ← 元のハッシュ）、バックアップのタグ名、ツリー一致の確認結果、
   サブモジュールの状態（未 push・遅れ）、push はしていないこと。claudeLog に追記する。

## スクリプトのテスト

```bash
python ~/.claude/skills/commit-squash/scripts/test_squash.py
```
使い捨てのリポジトリで、連続したまとめ・途中のツリー一致・未コミットのファイルの保持・undo・不正な計画（連続していない・抜け）で止まること、を確かめる。
squash.py を直したら流す。2026-10-06 に、判定（連続・網羅・最後のツリー）を 1 つずつ外すとテストが落ちることを確認済み。
