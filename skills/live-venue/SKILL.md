# ライブ会場の制作（最初の 1 回でこの水準を出す）

blender-stage（階層・マテリアル・UV・テクスチャ・FBX・アセット登録）の上に乗る。作法はそちら、ここは**ライブ会場ならではの中身と進め方**。
手本は `D:\_Personal\Project\BlenderScenes`（`vtuber_stage.blend` と `scripts/live_*.py`。2026-10-07 にユーザーと詰めた水準）。

この手順ができた理由: 2026-10-07 の会場は、組んだ後に 20 回以上直された。手戻りは 3 種類だった。
1. **作りの事実を知らずに組んだ**（LED を斜めの支柱で支えた、アレイの吊り方、サイドフィルの位置、袖と舞台の段差、客席に木）
2. **作り込みが足りなかった**（「プロップがあまりに粗く、淡白」「LED パネルの裏」）
3. **自分で見つけられなかった**（浮き・食い込み、壁の外にカメラを置いた真っ黒な撮影）

段階ごとの関門は、この 3 つを組む前に潰すためのもの。飛ばさない。

## 段階と関門

| 段階 | やること | 関門（次へ進む条件） |
|---|---|---|
| 0. 用途 | blender-stage の手順 0（Unity へ持ち込むか）。リファレンスを `references/` に集める | 用途とリファレンスが決まった |
| 1. 中身の洗い出し | 下の「会場にあるもの一式」を表にし、リファレンスと照らして要・不要・寸法を埋める。寸法は写真から割り出す（下の「寸法の割り出し」） | **表をユーザーに見せて確認を取った** |
| 2. 施工の調査 | 大きな機材ごとに、メーカーの仕様書・取扱説明書で「何に支えられ、何から吊るか・上限」を調べて表にする | 表の全行に出典がある。出典の無い施工で形を作らない |
| 3. 組む | 躯体 → ステージ・袖・舞台裏 → LED・トラス・吊り → PA → 客席 → 設備 → 小物。部品キットを使う | 段階ごとに点検（5）を通す |
| 4. 作り込み | 「品質の基準」の部品一覧まで作る | 全プロップが基準の部品を持つ |
| 5. 点検と撮影 | `scripts/venue_check.py` | 浮き 0・食い込み 0（許す組は理由付き）・階層 0。全シートを自分で見た |
| 6. 現場目線のレビュー | サブエージェントに下のひな形で依頼 | Medium 以上を直した |
| 7. 報告 | 罫線の後に、変更点ごとの画像を添えて | FBX はユーザーが「書き出して」と言ったときだけ |

**優先順位**: ユーザーの指示 > リファレンス > 下の「既定の作り」。既定はリファレンスに写っていない所を埋めるためのもので、
リファレンスとぶつかったら（例: 間口 10m・奥行 5m のライブハウスに「奥行 8m」）リファレンスを取り、表にそう書く。
ただし施工の事実（2 の表）はリファレンスより優先する（写真の見え方より、実際に立つ作りを取る）。

**寸法の割り出し**: 写真の中の大きさの分かる物を物差しにする。人（約 1.7m）・LED パネル（500mm 角。継ぎ目を数える）・
ボックストラス（30cm 角・定尺 3m）・鉄柵（1 枚 2m 前後・高さ 1.1〜1.2m）・扉（2.0〜2.4m）・客席の段（0.35〜0.45m）。
会場の名前が分かれば、公式の図面・座席表・技術資料（ステージの寸法・吊り点・電源）を先に探す。割り出した値は出典付きで表に書く。

## 1. 会場にあるもの一式（洗い出しの表の行）

リファレンスに写っていなくても、実在の会場にあるものは入れる（無いと「淡白」になる）。要らないと決めたものは理由を書く。

- **建物**: 床・壁（腰壁・吸音パネル）・天井（吊りパイプの格子 = 吊り物はすべてここから）・2 階席（段床・座席・手すり壁・柱・階段）・扉（両開き・誘導灯・金物）・ドリンクカウンター・ダクト・ケーブルラック・スプリンクラー・客電・消火器

- **映像**: メイン LED・柱・ヘッダー・吊り箱・サービスモニター（**舞台の左右に吊る**）
- **トラス・照明**: タワー（足の鉄板・ジャッキ）・上のトラス・中央のトラス・客席の上のトラス（チェーンモーターで吊る）・灯体（位置だけ。作り込まない）
- **PA**: メインのラインアレイ（吊り）・サブウーファー・フロントフィル・2 階下のディレイ・（幅が広い会場は）アウトフィル
- **演者向け**: 足元のモニター（ウェッジ）・サイドフィル（**袖の際の舞台の中ほど**）・マイクスタンド・床のケーブル・バミリ

## 3. 組む（部品キット）

```python
import importlib, sys
sys.path.insert(0, r"D:\_Personal\Project\BlenderScenes\scripts")
import live_parts as P, live_props as K
for m in (P, K): importlib.reload(m)
```

**そのまま呼べるキット**（会場の寸法に依存しない。引数だけで形が決まる）:
- `live_parts`: `Shape`（box / cyl / quad / drape で形を積み、`to_object` で 1 メッシュに）、`truss`、`moving_head`、
  `materials(tex_dir)`（texlib の模様とノーマルマップ付きのマテリアル一式。`tex_dir` は生成した PNG を置くフォルダ = `.blend` の隣の
  `<会場名>_textures`。blender-stage の「画像は .blend の隣の textures/」と同じ考え）、`pleat_amplitude`
- `live_props`: `Parts`（部品名 → 形 + マテリアル。`merge` で組み合わせ、`build` で単位の下へ）、`speaker`（full / sub / small）、`wedge`、
  `road_case`、`console`（audio / light）、`mic_stand`、`extinguisher`、`cable_reel`、`intre`、`at` / `rot_z`
- 単位の Empty は `stagelib.empty` + `stagelib.parent_to(world_authored=False)`（手本の `live_stage.unit` と同じ 3 行）

**写して寸法を引数にする手本**（手本の会場の定数 `live_stage.*` を直に読む。そのまま呼ぶと手本の寸法で組まれる）:
- `live_pa.line_array`（アレイの角度の決め方・吊り枠・ブライドル。`ARRAY_TOP_Z` は手本の 2 階席の耳の高さから決めた値）
- `live_detail.cube_rig`（吊り箱の吊り具）、`live_fittings._cabinet_backs`（LED パネルの背面。寸法は `LED_*` の定数）
- `live_detail.bevel_all`（面取りの規則。ルート名と名前の接頭辞が手本の会場のもの）
写すときは、読んでいる `L.*` を引数か新しい会場のモジュールの定数に置き換え、決め方（式とコメントの根拠）は残す。

新しい会場は、手本の `live_stage.py` を写して寸法を変えるのではなく、**キットを呼んで組む**（手本の寸法は手本の会場の事情を含む）。
数値は「理論で組む（他の寸法からの式）」か「実在の値（出典付き）」のどちらか。コメントに根拠を書く。

## 4. 品質の基準（部品一覧。これより少ないプロップは「淡白」と言われる）

- **スピーカー**: 胴・グリル・縁・ポート・銘板・角の金物・取っ手（`speaker`）。サブとフルレンジは別の顔
- **ウェッジ**: 傾いた胴・グリル・縁・銘板・角・取っ手（`wedge`）
- **卓**: 本体・手前の肘置き・フェーダーのつまみ・ノブ・溝・ボタン・画面・メーター（`console`）。台・モニターと脚
- **ハードケース**: 胴・縁の金物・留め具・取っ手・名札・キャスター（`road_case`）
- **LED パネルの背面**: 外周の枠・肋・電源ボックス（放熱フィン）・電源と信号のコネクタ（左が入力・右が出力）・ロック・取っ手・隣へのジャンパー
- **イントレ**: 支柱・ジャッキ・継ぎ目・横架材と補剛材・筋交（前後の面）・布板・手すり・中桟・幅木・重り・控え・はしご・単管とクランプ
- **扉**: 扉板 2 枚（原点は蝶番）・枠・押し棒・ドアクローザー・蹴り板・蝶番・誘導灯と金具
- **幕**: 箱で作らない。ひだ 50cm ごと・布 1 割増し（深さ約 ±5cm）・間隔と深さを不揃いに・裾ほど開く・スムーズシェーディング・厚み 1cm（`Shape.drape`）
- **ケーブル**: 機材から床へ下り、通り道（帯）に沿って袖まで這う。宙を横切らない
- 全プロップ: 面取り（`live_detail.bevel_all` の規則）、模様とノーマルマップ付きのマテリアル（単色の板にしない）

## 既定の作り（ユーザーに直された点。最初からこの形で作る）

- ステージは客席の正面の壁に埋め込む。壁の裏の袖と舞台裏はステージと同じ高さの地続きの床（袖だけ低くして階段で上がる形は「切れていて違和感」）
- 奥行は 8m 程度（16m 幅で 10m は深すぎた）。袖幕と客席の上のトラスは最初から入れる
- サービスモニターは舞台の左右に吊る（壁付け・2 階の張り出しの下ではない）
- サイドフィルは袖の際の、前と後ろの袖幕の間（舞台の中ほど）。LED の脇の奥に置かない
- 柵は最前も中柵も鉄柵（移動式のバリケード）
- 客席側に木を使わない（腰壁・手すり壁・カウンターは黒い化粧パネル、2 階は濃い灰色のタイルカーペット）
- 灯体は位置が分かる程度の仮のもの（後からユーザーが別で置く）。人型（等身大）をワールドの原点に置く。タイツは要らない
- 回る部品（灯体の頭・扉板・せりの床板）は、原点を回転軸・蝶番に置いて固定の部品と別の単位にし、回る範囲で寸法を決める

## 5. 点検と撮影

保存した .blend を**別プロセスの Blender** で開いて流す（共有中の Blender を止めない。run_python の 120 秒の上限にも当たらない）。

```bash
"D:/_Personal/Tools/Blender 5.2/blender.exe" -b <file.blend> --factory-startup \
  -P ~/.claude/skills/live-venue/scripts/venue_check.py -- \
  --root LiveHall --out <出力フォルダ> --allow <許す組.json>
```

- 結果は `report.json`（階層・浮き・食い込み。場所は center）と `sheet_wide_*.png`（全体 8 枚）・`sheet_units_*.png`（全単位の寄り）。
  終了コード: 0 = 問題なし / 1 = 階層・浮き・食い込みのどれかが出た / 2 = スクリプトが落ちた。
- 単位（まとまり）は ルート > 区分 > 単位 の単位。単位の中の入れ子（回る部品の軸の Empty・部品の子の部品）はまとめて 1 つ。
- 許す組（つなぐ作りとして重ねたもの: トラスとスリーブ、ケーブルと機材）は `[a, b, 理由]` の並びの JSON に置く
  （a・b は fnmatch のパターン。手本は `BlenderScenes/scripts/live_allow.json`）。理由の書けない組は許さず直す。
- 限界: 食い込みの深さは面までの最短距離なので、薄い板の中では板の厚みの半分までしか出ない（板を突き抜けた物も浅く出る）。
  幕・パネルのような薄い物を貫く物は、寄りの画で見て確かめる。
- **全シートを自分で見る**。見るところ: 支えが無い・吊り元が無い・宙を横切るケーブル・人の通れない通路・頭がつかえる高さ・単色の板・平らな幕・壁の外から撮った真っ黒な画。

```

観点: 支え（何に載り、何から吊るか。倒れないか）・吊り（吊り点・開き角・吊りパイプ）・配線の通り道・人の動線と通路の幅・
頭上の高さ・袖と舞台裏の使い勝手・材質（客席に木が無いか）・由来の書かれていない数値・点検（venue_check）が偽陽性で通っていないか。
```

## 先に読む（踏んだ罠）

- **カメラを壁の外に置くと真っ黒になる**（2026-10-07 に 3 回）。撮影は `venue_check.py` か、会場の外形の内側の座標で。
- **run_python は 120 秒で打ち切られる**。会場一式の点検・撮影は別プロセスで流す。
- **BVH の `overlap` は、同じ平面に面が並ぶ箱どうしの交差を返さない**。食い込みは `blender_mesh_overlaps`（外形の重なりも候補にし、面の上にも点を打つ）で見る。
- **斜めの管の下端を床の高さに置くと、管の側面が床へ沈む**。下端は管の半径の高さに置く（ケーブルリールの脚）。
- **壁に付ける物は、いちばん太い所で壁から離す**（消火器の胴の半径で離すと、底のゴムが壁に 4mm 入った）。
